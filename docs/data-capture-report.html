3. Who can read what

  • Email, registration code and Q1–Q8 answers are returned only with an admin login; anyone else gets nothing, including through the participant API. verified
  • Both exports are admin-only. The research CSV contains no email (checked: no “@” anywhere in the file).
  • Unsent questionnaire answers live only in the participant's browser tab and disappear when it is closed.

4. Know before you analyse

  1. Response time = milliseconds from the scenario appearing to the confirm click that saved the answer, including revealing the edges and moving the slider. A page refresh restarts the clock for that scenario. Answers in the production run were made by a test robot (~1.2 s); real participants will be much slower.
  2. Presentation order: participants see their five scenarios in the order of the answers array (also given by Answered At), not in the order the session lists them.
  3. Answered At in the research CSV is a raw epoch-milliseconds number (e.g. 1794915168150), unlike the other time columns, which are ISO dates. It is exact; convert with as.POSIXct(x/1000, origin="1970-01-01") or pd.to_datetime(x, unit="ms").
  4. Partner decisions are random draws. The production log shows matched=0/5 for every participant: no real partner answer is used (BUG-008, left as is by decision).
  5. Same person, two devices: a second device with an already-used registration code is accepted and paid (EC-8). Check the payment ledger for repeated registration codes and mark duplicates invalid before paying.
  6. Participants who stop part-way keep their saved answers (Submission Completed = false) and are in the research CSV but not in the payment ledger.

Not needed for the current analysis plan; say so if any of these is.

  • Device type / browser (only the fingerprint ID).
  • Consent: the app keeps no consent record of its own.
Open before launch
  • Bot check can be bypassed. The “passed Turnstile” cookie is not signed, so a script can skip the bot check by setting it (this is also how the automated production test got through, so the real Cloudflare check itself was not tested). Fix: sign the cookie on the server.
  • Database backups were not checked. Confirm backups are enabled on the MongoDB cluster before real data arrives.
